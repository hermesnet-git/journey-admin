Design-time

O Portal Administrativo: onde a jornada é construída

É onde um produto é cadastrado, uma jornada é modelada visualmente, cada tela é composta a partir de um catálogo corporativo de componentes e as integrações necessárias são configuradas. Ao final, um clique publica tudo como uma versão imutável, pronta para ser executada.

Ao publicar, o Back Admin envia o fluxo para o Runtime e, em paralelo, cada tela para o repositório de especificação corporativo.

Detalhe técnico — domínios e fluxo de publicação
A arquitetura lógica do Portal Administrativo tem 11 domínios agrupados em 6 grupos funcionais: Administração, Autoria, Publicação, Governança de Acesso, Governança Operacional e Observabilidade Técnica. Na publicação, o back admin faz duas chamadas de saída: uma para o serviço que transforma o fluxo em processo executável e o implanta no Runtime, e outra para o serviço guardião do catálogo SDUI, que grava o envelope de cada tela no repositório de especificação (Strapi). O Runtime Engine nunca conhece o domínio do Portal Administrativo, nem acessa suas APIs diretamente.
  • Componentes SDUI: catálogo corporativo com 19 componentes em 5 níveis de composição.
  • Toda árvore de tela referencia componentes por tipo + versão, nunca por chave interna.
  • Ao publicar, a árvore da tela é congelada no snapshot: editar o catálogo depois não afeta jornadas já publicadas.
  • O modelador também permite gerar um rascunho de fluxo assistido por IA, revisável como qualquer edição manual.
