Guia de integração

Sumário

Integre seu canal ao Elastic Journey

Este guia mostra como um canal digital (site, app ou WhatsApp) executa as jornadas publicadas no Elastic Journey. Seu canal faz poucas chamadas ao serviço de jornadas: inicia a jornada, recebe a etapa atual, desenha a tela que vem descrita na resposta e devolve o que a pessoa preencheu. A ordem das telas, as decisões e as integrações ficam na plataforma.

Comece pelo Começo rápido para ver uma jornada rodando. Conceitos explica os termos usados no guia, Tarefas mostra como resolver cada situação e Referência detalha rotas, campos e erros.

1. Começo rápido

Você vai precisar do endereço do serviço de jornadas (no ambiente local, http://localhost:8085/api/v1) e do identificador (journeyId) de uma jornada publicada para o seu canal.

1. Inicie uma instância

Mande as variáveis de entrada que a jornada pede e diga de qual canal você está chamando.

curl -X POST "http://localhost:8085/api/v1/journeys/{journeyId}/instances?channelType=WEB" \
  -H "content-type: application/json" \
  -d '{ "cpf": "12345678900" }'

A resposta traz o identificador da instância e a primeira etapa:

{
  "processInstanceId": "a41f0c2e-…",
  "businessKey": "6d2b9e10-…",
  "flow": { "channelTypes": ["WEB", "MOBILE"], "flowNodes": [ … ] },
  "step": {
    "type": "USER_TASK",
    "taskId": "8f1c2d4e-…",
    "nodeId": "Node_5b0e…",
    "nodeName": "Seus dados",
    "nodeType": "USER_TASK",
    "form": { "name": "Seus dados", "sdui": { … }, "context": { … } },
    "errorMessage": null
  }
}

Guarde o processInstanceId: ele identifica a instância em todas as chamadas seguintes.

2. Desenhe a etapa

Quando step.type é USER_TASK, a tela está em step.form.sdui. Os textos já chegam preenchidos; seu canal desenha os componentes, cuida dos campos, da validação e dos botões (veja Desenhar uma tela).

3. Envie as respostas

Quando a pessoa tocar no botão de envio, mande o que ela preencheu junto com o taskId da etapa.

curl -X POST "http://localhost:8085/api/v1/instances/{processInstanceId}/tasks/{taskId}/complete" \
  -H "content-type: application/json" \
  -d '{ "answers": { "nome": "Ana Souza" } }'

A resposta já é a próxima etapa, no mesmo formato de step. Se ela vier com errorMessage, é a mesma tela de novo: mostre a mensagem e deixe a pessoa tentar outra vez.

4. Repita até o fim

Em WAITING, a jornada está processando algo e ainda não há tela; consulte a etapa de novo depois de alguns segundos. Em ENDED, a jornada terminou.

curl "http://localhost:8085/api/v1/instances/{processInstanceId}/current-step"

O laço inteiro

O mesmo roteiro em TypeScript, usando apenas fetch. A função desenharTela é a parte do seu canal: desenha a tela e resolve quando a pessoa enviar.

const BASE = 'http://localhost:8085/api/v1';

async function chamar(method: string, path: string, body?: unknown) {
  const resposta = await fetch(BASE + path, {
    method,
    headers: { 'content-type': 'application/json' },
    body: body === undefined ? undefined : JSON.stringify(body),
  });
  const texto = await resposta.text();
  const json = texto ? JSON.parse(texto) : null;
  if (!resposta.ok) throw new Error(json?.message ?? `HTTP ${resposta.status}`);
  return json;
}

let { processInstanceId, step } = await chamar(
  'POST', `/journeys/${journeyId}/instances?channelType=WEB`, { cpf: '12345678900' });

while (step.type !== 'ENDED') {
  if (step.type === 'WAITING') {
    await new Promise((fim) => setTimeout(fim, 3000));
    step = await chamar('GET', `/instances/${processInstanceId}/current-step`);
    continue;
  }
  const answers = await desenharTela(step.form, step.errorMessage);
  step = await chamar('POST', `/instances/${processInstanceId}/tasks/${step.taskId}/complete`, { answers });
}

2. Conceitos

Seu canal conversa só com o serviço de jornadas e só precisa conhecer os termos abaixo.

O ciclo de uma etapa

Iniciar também pode levar direto a uma espera ou ao fim, quando a jornada começa processando algo. Trate sempre os três tipos.

3. Tarefas

3.1 Iniciar com variáveis de entrada

Para saber quais variáveis a jornada espera, consulte o fluxo e procure o nó com type igual a START: o campo startVariables lista nome e tipo de cada uma. Confira também se o seu canal está em channelTypes. 

curl "http://localhost:8085/api/v1/journeys/{journeyId}/flow"
{
  "channelTypes": ["WEB", "MOBILE"],
  "flowNodes": [
    { "id": "Node_01a…", "type": "START", "name": "Início",
      "startVariables": [ { "name": "cpf", "type": "string" }, { "name": "limite", "type": "number" } ] },
    …
  ]
}
  • Todas as variáveis declaradas são obrigatórias. Faltando alguma, a instância não é criada e a resposta é 409 com a lista do que faltou.
  • Tipos. number e boolean são convertidos (aceitam número ou texto); string, date e datetime são guardados como texto. Para datas, envie no padrão ISO 8601.
  • Variáveis extras, que a jornada não declara, também são aceitas e ficam disponíveis para ela.
  • channel é reservado. O serviço o preenche com o channelType da chamada; não envie no corpo.

3.2 Desenhar uma tela

Numa etapa USER_TASK, o campo form traz a tela (sdui) e os valores que ela usa (context). Exemplo abreviado:

"form": {
  "name": "Seus dados",
  "context": { "data": { "data_cpf": "12345678900" }, "form": { "data_cpf": "12345678900" } },
  "sdui": {
    "schemaVersion": "1.0.0",
    "catalogVersion": "1.0.0",
    "journeyVersion": 3,
    "uiStepId": "Node_5b0e…",
    "supportedTargets": ["react.web", "react.mobile", "flutter.web", "flutter.mobile", "whatsapp"],
    "minRendererVersion": {},
    "dataSources": {},
    "data": ["ui.screen", { "id": "tela", "version": "1.0.0", "title": "Seus dados" }, [
      ["ui.text", { "id": "t1", "version": "1.0.0", "text": "Confirme seus dados, CPF 12345678900" }],
      ["ui.textInput", { "id": "nome", "version": "1.0.0", "label": "Nome completo", "required": true,
        "$bindings": { "value": { "path": "form.nome", "mode": "twoWay" } } }],
      ["ui.button", { "id": "ok", "version": "1.0.0", "label": "Continuar",
        "$events": { "onPress": { "action": "action.submit" } } }]
    ]]
  }
}

1. Confira a compatibilidade. O seu alvo (react.web, react.mobile, flutter.web, flutter.mobile ou whatsapp) precisa estar em supportedTargets, e a versão do seu renderizador precisa atender minRendererVersion. Se não atender, não desenhe a tela pela metade: mostre que a etapa não está disponível neste canal.

2. Percorra a árvore. sdui.data é uma árvore de tuplas [tipo, atributos] ou [tipo, atributos, filhos], com raiz ui.screen. Todo componente tem id e version. Associe cada tipo a um componente seu (lista em Componentes).

3. Use o que já veio pronto. O serviço já resolveu a tela antes de entregar:

  • textos com {{form.x}} e {{data.x}} já chegam com o valor no lugar;
  • cada vínculo de $bindings já traz o valor atual no atributo de mesmo nome (um campo revisitado chega com value preenchido);
  • opções de ui.select e itens de ui.selectList já vêm montados;
  • dataSources vem sempre vazio: o canal nunca busca dados por conta própria.

4. Faça a sua parte.

  • Estado dos campos. Guarde o que a pessoa digita nos campos com vínculo twoWay em form.*. É isso que vira resposta.
  • Visibilidade e habilitação. $visibility e $active são condições { rule, path, value } com as regras equals, notEquals, in e notIn. Reavalie enquanto a pessoa preenche. Para form.x, use o valor atual do campo; para data.x, o valor em form.context.data com o nome data_x; para channel, o seu canal. Num contêiner, a condição vale para tudo o que está dentro. disabled: true sempre prevalece sobre $active.
  • Validação. Antes de enviar, valide os campos visíveis e ativos: required, maxLength e as regras da lista validation (cada uma com rule, value e message, como required e minLength).
  • Eventos. $events liga um evento do componente (onPress, onDismiss, onAction) a uma ação. O que cada ação faz está em Ações.

3.3 Enviar as respostas

Na ação action.submit, valide e chame o concluir com o taskId da etapa:

curl -X POST "http://localhost:8085/api/v1/instances/{processInstanceId}/tasks/{taskId}/complete" \
  -H "content-type: application/json" \
  -d '{ "answers": { "nome": "Ana Souza", "aceite": true, "botao": "confirmar" } }'
  • Chaves. Cada chave é o caminho do vínculo sem o form.: o campo ligado a form.nome vai como nome.
  • Só o que está à vista. Campos ocultos ou desabilitados não entram. Valores nulos são ignorados.
  • Qual botão foi usado. Se o action.submit tiver params: { "path": "form.botao", "value": "confirmar" }, acrescente botao: "confirmar". É assim que a jornada sabe qual botão a pessoa escolheu.
  • Lista de seleção. Envie o item escolhido (vínculo value) e a ação escolhida (vínculo action).
  • Tipos. Campo de texto com inputMode number ou decimal é guardado como número; ui.checkbox, como verdadeiro ou falso; os demais, como texto.

Use sempre o taskId da etapa que está na tela. Se ele não for mais o da etapa aberta (por exemplo, num segundo toque no botão), a resposta é 409 e nada muda. Desabilite o botão enquanto o envio estiver em andamento.

3.4 Tratar uma etapa em espera

WAITING quer dizer que a jornada está processando algo fora da tela: aguardando uma mensagem, uma integração ou um prazo. A etapa traz nodeName e nodeType, só para informação. O serviço não avisa quando a espera termina: mostre um estado de aguardando e consulte current-step de novo, num intervalo adequado à jornada, até vir uma tela ou o fim.

3.5 Botão Voltar

Um botão com action.navigate e params: { "route": "voltar" } pede a tela anterior, sem concluir a atual:

curl -X POST "http://localhost:8085/api/v1/instances/{processInstanceId}/back"

A resposta é a etapa anterior, já com os valores preenchidos antes. Quando não dá para voltar, a resposta é a mesma etapa com errorMessage, por exemplo “Não há tela anterior para voltar.” ou “Não é possível voltar: a operação desta etapa já foi registrada.” (o que já foi gravado num sistema não se desfaz). Outros valores de route são destinos do seu próprio canal.

3.6 Tentar novamente

Alguns componentes mostram dados buscados na hora em que a tela é montada. Se essa busca falhar, o componente chega com loadError: { message, required }. Mostre a mensagem e ofereça a ação action.retry, que é só consultar current-step de novo: a tela é montada outra vez. Quando required é true, a etapa não pode ser enviada até a busca dar certo.

3.7 Encerrar

Para cancelar uma instância em andamento (a pessoa desistiu, a sessão expirou):

curl -X DELETE "http://localhost:8085/api/v1/instances/{processInstanceId}"

Encerrar uma instância que já terminou não é erro. Depois disso, consultar a etapa devolve ENDED.

3.8 Tratar erros

Os erros chegam de dois jeitos, e o seu canal precisa tratar os dois:

  • Resposta 200 com errorMessage. A etapa voltou igual, com uma mensagem para a pessoa. Acontece quando uma integração falhou ao concluir a tela (nada foi gravado; dá para tentar de novo) ou quando o Voltar foi recusado. Mostre a mensagem e mantenha o que a pessoa já preencheu.
  • Resposta HTTP de erro. O pedido não foi atendido. A tabela de códigos de erro diz o que cada um significa.

4. Referência

4.1 Rotas

Todas as rotas ficam sob /api/v1. Corpo e resposta são JSON (content-type: application/json). A forma de autenticação está em definição.

4.6 Códigos de erro

O corpo de erro é { "timestamp", "status", "code", "message" }; mostre ou registre o message. Em alguns erros internos o corpo traz só type e message.

StatusQuandoO que fazer
409O taskId não é o da etapa aberta; a instância não está numa tela (Voltar); faltou variável de entrada obrigatória; a jornada não está publicada.Consulte a etapa atual e siga a partir dela. No iniciar, confira o journeyId e as variáveis.
502A plataforma não conseguiu completar a operação agora.Ofereça tentar de novo mais tarde.
500Erro inesperado.Registre o message e ofereça tentar de novo.

Consultar a etapa de uma instância que não existe devolve ENDED, não 404. Guarde o processInstanceId com cuidado.

5. Checklist de prontidão

Antes de levar a integração para produção, confira:

  • Trata os três tipos de etapa, inclusive quando o iniciar já devolve espera ou fim.
  • Confere supportedTargets e minRendererVersion antes de desenhar.
  • Desenha todos os componentes do catálogo v1 usados pelas jornadas do canal.
  • Reavalia $visibility e $active enquanto a pessoa preenche, inclusive em contêineres.
  • Valida antes de enviar e envia só campos visíveis e ativos.
  • Envia o valor do botão escolhido quando o action.submit traz params.
  • Desabilita o envio enquanto a chamada está em andamento.
  • Mostra errorMessage mantendo o que a pessoa já preencheu.
  • Em espera, consulta a etapa de novo num intervalo definido, com limite de tempo.
  • Implementa o Voltar e o Tentar novamente.
  • Abre só URLs http/https de domínios permitidos.
  • Trata 409 consultando a etapa atual, e 502/500 com opção de tentar de novo.
  • Tem tempo limite em todas as chamadas.
  • Guarda o processInstanceId para retomar a jornada e encerra a instância quando a pessoa desiste.
